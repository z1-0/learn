AI 论文术语表

参考文档持续更新

阅读 AI 论文时最常遇到的关键术语，按主题分组。每个术语包含英文原文、中文翻译和一句话解释。

基础概念

LLM (Large Language Model) — 大语言模型

基于海量文本训练的语言模型，核心能力是预测下一个 token。通过这个简单目标，涌现出理解、推理、代码生成等能力。代表：GPT-4、Claude、Llama。

Token — 词元

模型处理文本的最小单位。一个 token ≈ 0.75 个英文单词，或 ≈ 1.5 个中文字。模型的所有输入输出都以 token 计数。"Hello world" 可能被切分为 ["Hello", " world"] 两个 token。

Parameter — 参数

模型的"神经元"权重。参数量越大，模型容量越大。7B = 70 亿参数，70B = 700 亿参数。参数数量直接影响显存需求和推理速度。

Training — 训练

让模型从数据中学习的过程。核心是前向传播（计算预测结果）→ 计算损失（对比预测与正确答案的差距）→ 反向传播（调整参数减小损失）的循环。

Inference — 推理

使用训练好的模型生成输出的过程。推理时模型权重不再更新，只是根据输入计算输出。也称"前向传播"或"生成"。

Context Window — 上下文窗口

模型一次能"看到"的最大 token 数量。GPT-4 是 128K，Claude 是 200K，Gemini 是 1M+。超出窗口的内容模型无法感知。

Temperature — 温度

控制输出随机性的参数。T=0 时输出确定性最高（总是选概率最高的 token），T=1 时多样性最大。代码生成通常用 T=0~0.2，创意写作用 T=0.7~1.0。

架构

Transformer

2017 年 Google 提出的架构，几乎所有现代 AI 模型的基础。核心创新：自注意力机制 (Self-Attention) 让模型能同时关注输入序列中的所有位置，而非像 RNN 那样逐个处理。论文：Attention Is All You Need (Vaswani et al., 2017)。

Attention — 注意力机制

让模型在处理一个 token 时"关注"输入中其他相关 token 的机制。例如在翻译 "The animal didn't cross the street because it was too tired" 时，"it" 需要关注 "animal" 而非 "street"。

Self-Attention — 自注意力

注意力的一种，序列中的每个位置关注同一序列中的其他位置。Transformer 的核心组件。

Decoder-Only Architecture — 仅解码器架构

当前主流 LLM 的架构（GPT、Claude、Llama）。只有 Transformer 的解码器部分，擅长文本生成（自回归：逐个 token 预测）。与之对比的 Encoder-Only 架构（BERT）擅长理解（分类、提取）。

MoE (Mixture of Experts) — 混合专家模型

将一个模型拆分为多个"专家"子网络，每次只激活其中一部分。可以在不增加推理计算量的前提下大幅增加总参数量。代表：Mixtral 8x7B、GPT-4、DeepSeek-V2。

Embedding — 向量表示

将文本（或图像、音频）映射到高维空间中的向量。语义相近的文本在向量空间中的距离也近。用于搜索、聚类、RAG。常用模型：text-embedding-3-small、BGE。

训练范式

Pre-training — 预训练

在超大规模数据上训练模型，目标是学习通用的语言知识。这是最昂贵的阶段（数万 GPU 小时）。产出的是"基础模型"（base model），能续写文本但不听话。

Fine-tuning — 微调

在预训练模型基础上，用更小、更高质量的数据集继续训练，让模型学会特定行为或格式。分为指令微调 (Instruction Tuning / SFT) 和任务微调。

SFT (Supervised Fine-Tuning) — 有监督微调

用人工标注的指令-回答对训练模型，让它学会遵循指令。这是从"基础模型"到"助手模型"的关键步骤。

RLHF (Reinforcement Learning from Human Feedback) — 基于人类反馈的强化学习

让模型输出更符合人类偏好的训练方法。流程：SFT → 训练奖励模型（Reward Model）→ 用强化学习（PPO）优化策略。ChatGPT 的核心技术之一。

DPO (Direct Preference Optimization) — 直接偏好优化

RLHF 的简化替代方案。不需要训练独立的奖励模型，直接用偏好对（好回答 vs 差回答）优化模型。更简单、更稳定。

Quantization — 量化

降低模型参数精度（如从 16-bit 降到 4-bit），在几乎不损失质量的前提下大幅减少显存占用。4-bit 量化可将 70B 模型从 ~140GB 降到 ~35GB

Distillation — 蒸馏

用一个大模型（教师）的输出训练一个小模型（学生）。小模型学习模仿大模型的行为，获得接近的能力但成本低得多。

Agent

Agent — 智能体

能自主感知环境、做出决策、采取行动来完成目标的系统。在 AI 语境中，Agent = LLM + 工具 + 记忆 + 规划。核心区别：Agent 会主动推理并行动，而非被动回答问题。

Tool Use / Function Calling — 工具调用

LLM 调用外部函数/API 的能力。模型生成结构化的函数调用请求，由宿主系统执行并返回结果。这是 Agent 与外部世界交互的基础。

ReAct (Reasoning + Acting) — 推理+行动

一种 Agent 范式，让模型交替进行推理（思考下一步）和行动（调用工具/收集信息）。核心论文：ReAct: Synergizing Reasoning and Acting in Language Models (Yao et al., 2023)。当前多数 Agent 框架的基础。

Code Agent — 编码智能体

专注于编程任务的 Agent。能理解代码库、编写代码、运行测试、调试。代表：Devin、Claude Code、SWE-agent、Cursor。Code Agent 的核心能力包括：代码理解、编辑执行、错误恢复、长上下文管理。

Planning — 规划

Agent 将复杂任务分解为子步骤的能力。可以是单次规划（一次分解全部步骤）或动态规划（边执行边调整）。多种方法：Chain-of-Thought、Tree-of-Thought、ReAct。

Memory — 记忆

Agent 在对话/任务中保持状态的能力。分为短期记忆（上下文窗口内）和长期记忆（通过外部存储持久化，如 RAG、向量数据库）。

RAG (Retrieval-Augmented Generation) — 检索增强生成

在生成回答前，先从外部知识库中检索相关信息，然后让模型基于检索结果生成。解决 LLM 知识过时和幻觉问题。流程：Query → 检索相似文档 → 拼接上下文 → LLM 生成。

MCP (Model Context Protocol)

Anthropic 提出的开放标准协议，定义 LLM 应用与外部工具/数据源之间的通信方式。类似于"AI 应用的 USB-C 接口"。让 Agent 能统一地接入文件系统、数据库、API 等。

评估与指标

Pass@k

代码生成的标准评估指标。生成 k 个候选答案，只要有一个能通过测试就算成功。通常报告 Pass@1（一次生成就正确）和 Pass@k（k 次中至少一次正确）。

Perplexity (PPL) — 困惑度

衡量模型对文本预测能力的指标。越低越好。PPL=1 是完美预测，越高表示模型越"困惑"。主要用于评估预训练质量，但和实际任务表现不一定正相关。

Benchmark — 基准测试

标准化评估数据集，用于比较不同模型的能力。常见：MMLU（知识推理）、HumanEval（代码生成）、GSM8K（数学推理）、SWE-bench（代码修复）。

SWE-bench

评估 Code Agent 能力的标准基准。包含来自真实 GitHub 仓库的 issue + PR 对。Agent 需要理解 issue、修改代码、通过测试。是 code agent 领域的"ImageNet 时刻"。

实践技术

Prompt Engineering — 提示工程

设计输入提示以引导模型输出的技术。包括：Few-shot（给示例）、Chain-of-Thought（让模型逐步推理）、System Prompt（设定角色和行为边界）。

Chain-of-Thought (CoT) — 思维链

让模型在给出最终答案前先生成中间推理步骤。显著提升复杂推理任务的准确率。可以结合 Few-shot 使用（给推理示例）或 Zero-shot CoT（直接在提示中加 "Let's think step by step"）。

Few-shot / Zero-shot — 少样本/零样本

Zero-shot：不给示例直接让模型完成任务。Few-shot：在提示中给几个输入输出示例。Few-shot 通常效果更好，但消耗更多 token。

平台与生态

arXiv

预印本服务器，几乎所有 AI 论文都会先发在这里。域名为 arxiv.org。论文编号格式：arXiv:2305.18290（代表 2023 年 5 月，第 18290 篇）。

Papers with Code

网站 (paperswithcode.com)：将论文与代码实现、数据集、评估结果关联起来。可以直接看到某个任务的 SOTA (State-of-the-Art) 排行。

Hugging Face

AI 模型和数据集的"GitHub"。可以找到几乎任何开源模型（Llama、Mistral、DeepSeek 等），在线试用，查看模型卡（Model Card）了解训练细节和评估结果。
